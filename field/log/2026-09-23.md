## Evening — phases 7, 8, 9 (closing out)

    it timed out twice unattended.
12. **F-15 filed and fixed (#1033, PR #1034).** Found by asking a dull question — why does
    this repository have no CI runs? — and reading the answer instead of assuming it. The
    `.github/` directory was in `.gitignore`, and the workflow inside it, generated by
    `niha ci agent init`, pins `.github/actions/niha-ci@v1`. That ref has never existed:
    the repository tags full versions only, v1.0.0 through v1.2.8, and there is no `v1`
    branch. So the generated CI could never have run for anyone. Reproduced in a clean
    empty repo in two commands.
13. **Recovered two stranded artifacts.** `field/log/2026-09-23.md` — this file — and
    `field/sessions/README.md` existed only on `phase-5/plan`, which was never merged.
    Caught by looking for today's log to append to it and finding nothing there. Noting the
    mechanism because it is the same class as the `git reset --hard` incident yesterday:
    work that exists in git but not on the branch you are on is invisible until you look
    for it by name.
14. **Performance measured, and one budget deliberately left unproven.** Every request
    enters Vercel's Mumbai edge and executes in Washington DC (`x-vercel-id: bom1::iad1`),
    so ~230-250ms of every response is geography. All three endpoints sit at the same p50
    despite doing very different amounts of work. The NFR budgets are written server-side
    and I can only measure end to end from here, so `docs/performance.md` records the
    numbers and says the verdict is unproven rather than claiming a pass. The fix is
    configuration — function region `bom1`, Neon in `ap-south-1`, both or neither — and it
    is handover ticket 4.
15. **A clever fix reverted.** Two concurrent `npm test` runs corrupt each other, and the
    symptom is the concurrency test falsely reporting two bookings in one bay. I built an
    advisory-lock global setup; it worked, then hung indefinitely, because `DATABASE_URL`
    points at a pooled Neon endpoint where session-level advisory locks are not reliable. I
    had swapped a loud, correctly-diagnosed race for a silent hang. Reverted, and four
    sentences in the README instead. Recorded in the retrospective, because it is the same
    mistake as yesterday's session harness, made about forty minutes after I wrote down the
    lesson.
16. **`/api/health` was reporting `version: "unknown"` on every production deployment.** It
    read `npm_package_version`, which is only set when the process is launched *by npm*, and
    the Vercel runtime is not. Now reads `package.json` and also reports the deployed commit,
    so a health response identifies exactly what is running. The existing tests asserted the
    broken behaviour and were updated.
