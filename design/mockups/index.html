S1 — empty: no areas configured

Reached when /api/areas succeeds and returns an empty list — a database that has been migrated but not seeded, which is what every fresh deployment looks like before db-setup.sh runs. Distinct from the error state: nothing failed. Before this existed the screen rendered a form with no chips and a disabled button, which reads as broken rather than empty.

No areas are available yet

parkmitra has not been set up for any area in this city. Nothing is broken — there is simply nothing to book here yet.

S2 — permission denied: cannot occur

Searching requires no identity (ADR-002). There is nothing to be denied. Registered in design/states.md rather than mocked, because a mockup of an unreachable state is dead design that makes the real gaps harder to see.

S3 — empty: reached without a chosen bay

Added 2026-09-25, and this register previously said it could not occur. It can: anyone may open /book directly. The bay fetch returned early on missing parameters, so the screen rendered a booking form with no spot, no bay, no price, and a "Book this bay" button with nothing to book. A button that looks like it might work is worse than an error page.

S6 — permission denied: unknown or malformed code

The whole enumeration defence. An unknown code and a malformed one produce byte-identical responses, asserted by an end-to-end test. If they differed, an attacker would learn the format was right.
